# 순위 테이블 배치 재계산 + 바꿔치기 — MySQL

- 일시: 2026-10-19 00:37
- 인원: 1,000,000명, 점수 0~999,999 균등 난수(seed 42)
- 원본 `ranking(user_id PK, score, KEY(score, user_id))` → 순위 테이블 `ranking_snapshot(user_id PK, score, rnk UNIQUE)`
- 재계산: `INSERT INTO … SELECT user_id, score, ROW_NUMBER() OVER (ORDER BY score DESC, user_id DESC) FROM ranking`

> 적재 완료. 첫 재계산 3.4s

> 결과 일치 확인: Redis vs mysql-snapshot — 순위 200건 · 상위 100명 · 주변 ±5명 20건 · 깊은 페이지 1건 → 불일치 0건

## 1. 순차 조회 (클라이언트 1개, 200회 평균, 단위 ms)

| 연산 | redis | mysql (실시간 COUNT) | mysql-snapshot |
|---|---:|---:|---:|
| 내 순위 (무작위 유저) | 0.242 | 33.584 | 0.710 |
| 내 순위 (하위 1% 유저) | 0.256 | 63.516 | 0.723 |
| 상위 100명 | 0.354 | 0.752 | 0.821 |

> 재계산 후 `ANALYZE TABLE`을 안 하면 (새 테이블 통계가 "빈 테이블"):
> - 바꿔치기 직후 계획 `type=ALL, key=NULL, rows=20, Extra=Using where; Using filesort`, 첫 조회 106.470ms
> - 상위 100명 200회 평균 27.206ms, 측정 후 계획 `type=range, key=ix_rnk, rows=100, Extra=Using index condition` (백그라운드 통계 자동 재계산 여부에 따라 바뀜)
